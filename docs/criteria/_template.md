# 분석 기준(criterion) 작성 스키마 — 템플릿 v1

이 파일은 `docs/criteria/` 밑 카테고리별 기준 문서(예: `10-resilience.md`)에서
개별 criterion을 **같은 형식**으로 쓰기 위한 틀이다. 목적은 두 가지다.

1. **1차 분석(발견)** — 분석가/LLM이 "무엇을, 어디서, 어떤 신호로" 찾을지를 표준에 근거해 따라감.
2. **2차 검증(정오탐·누락)** — 각 발견을 그 criterion의 `오탐 함정`·`검증 방법`에 **기계적으로 대조**해
   확정/가설/기각으로 재분류하고, 아예 안 본 criterion(=커버리지 공백)을 집어냄.

> 핵심: 2차 패스가 "LLM이 LLM을 느낌으로 재검토"가 되지 않으려면, **판단 기준(oracle)이 발견보다 먼저 문서에 적혀 있어야** 한다.
> 그래서 criterion의 `오탐 함정`·`검증 방법` 칸이 이 문서 전체에서 가장 중요하다.

---

## criterion 행 스키마

각 criterion은 아래 필드를 모두 채운다. (값이 없으면 `-`가 아니라 "해당 없음/미해당" 사유를 짧게)

| 필드 | 설명 |
|---|---|
| **내부 ID** | `RES-ROOT-01` 형식. `<카테고리약어>-<주제>-<2자리>`. 보고서·노트에서 이 ID로 발견을 참조한다. |
| **제목** | 한 줄 요약 (예: "네이티브 su 경로 스캔 기반 루트 탐지") |
| **표준 매핑** | `MASVS: RESILIENCE-1` / `MASTG: MASTG-TEST-0324` / `MASWE: MASWE-0051` 형태. **실제 값만** 쓰고, live 사이트에서 확인 못한 ID는 뒤에 `⚠️ 미검증` 표기. |
| **적용 레벨** | `R`(resilience) / `L1` / `L2`. RESILIENCE 계열은 대부분 `R`. |
| **어디서 보나** | `jadx(Java)` / `ghidra(.so)` / `manifest` 중 해당되는 것(복수 가능). |
| **탐지 신호** | 구체 패턴. Java면 API·문자열·클래스명, 네이티브면 JNI 함수명·syscall·문자열 참조·분기 형태. "그럴듯한 추상 설명" 금지, grep 가능한 토큰 위주. |
| **오탐 함정(FP trap)** | 왜 그럴듯한 오답이 나오나. 무엇과 헷갈리나. (예: 로깅 문자열인데 탐지로 오인, 죽은 코드, 데모/디버그 전용 분기) |
| **검증 방법(oracle)** | 2차 패스가 확정/기각하는 **구체 절차**. ① 정적 교차대조(어느 Listing/어셈블리 주소·분기를 보나, xref가 실제 보안 흐름에 닿나) ② 동적 확인(Frida로 무엇을 후킹/관찰하면 참/거짓이 갈리나) ③ 확정에 필요한 최소 증거. |
| **우회 포인트** | resilience에서 필수. 어느 분기를 뒤집나(`if (detected) → NOP/반대로`), 어느 함수 반환값을 바꾸나, 어디를 후킹하나. 주소·함수명이 특정되면 적고, 아니면 "어떤 형태의 분기를 찾아 뒤집는지" 패턴으로. |
| **신뢰도 기본값** | 1차 발견 시 기본 신뢰도. RESILIENCE 정적 추론은 대부분 `가설`에서 시작. |
| **승급(확정) 조건** | 무엇이 충족되면 `확정`으로 올리나 (예: "어셈블리에서 분기 조건과 su 문자열 xref 동시 확인 + Frida로 반환값 뒤집었을 때 탐지 우회됨 재현"). |
| **금융 가중** | `예`/`아니오`. 금융·결제·인증 앱에서 특히 중대해 우선순위를 올리는 criterion이면 `예`. 일반 앱에도 적용되는 generic core는 유지하고, 가중 여부만 플래그. |

## 발견(finding)이 criterion을 참조하는 방식

분석 노트(`notes/native/<so>.md`, `notes/java_analysis.md`)에 발견을 적을 때 머리에 메타 블록을 붙인다:

```
### [RES-ROOT-01] 네이티브 su 경로 스캔 루트 탐지
- 신뢰도: 가설            ← 1차. 2차 검증 후 확정/기각으로 갱신
- 표준: MASVS-RESILIENCE-1 / MASWE-0051 / MASTG-TEST-0324
- 위치: libfoo.so  sub_12AB0  (ghidra)
- 근거: "/system/xbin/su" 문자열 xref → access() 호출 → 결과 분기
- 우회(가설): sub_12AB0 반환값 0 고정 또는 분기 뒤집기
- 2차 메모: (검증 패스가 채움)
```

## 신뢰도 어휘 (3단계)

| 값 | 의미 | 올리는/내리는 기준 |
|---|---|---|
| **가설** | 정적 디컴파일 추론만으로 세운 1차 판단. 난독화 `.so`에서 환각 가능. 기본값. |
| **확정** | 해당 criterion의 `승급 조건`을 만족(정적 교차대조 + 가능하면 동적 재현). 보고서에 단정 서술 가능. |
| **기각** | 2차 검증에서 `오탐 함정`에 해당함이 드러남(죽은 코드·로깅·데모 분기 등). 보고서에선 제외하거나 "오탐으로 배제" 기록. |

> 원칙: **1차는 전부 `가설`로 시작**한다. `확정`은 2차 검증을 통과한 것에만 부여한다.
> 이렇게 해야 CLAUDE.md의 "obfuscated security .so는 그럴듯한 틀린 pseudocode를 낸다 → Listing 교차검증" 규칙이 신뢰도 어휘로 강제된다.
