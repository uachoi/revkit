## 1. revkit 프로세스 전체 구조 (다시 봐도 헷갈리지 않게)

### 1-1. 명령 체인
`/rev-check` → `/rev-jadx` → **[Ghidra 수동 게이트]** → `/rev-native` → `/rev-report` (+ 2차 `/rev-verify`)
`<target>`은 항상 `targets/` 밑 폴더명(예: `scn00`). **매 호출마다 target 인자 필요**(명령은 target을 기억 안 함).
`/rev-all <target>`은 위를 한 번에 돌리되 **Ghidra 지점에서만 멈춤**.

### 1-2. 데이터 퍼널 (한 방향 — 각 단계 출력이 다음 단계 입력)
```
jadx → triage.md + java_analysis.md
         └(우선순위 체크리스트)→ rev-native → native/<so>.md
                                                  └→ rev-report → report.md + INDEX.md
rev-verify: native/java 노트의 발견을 '가설→확정/기각'으로 재분류 + 커버리지 공백 점검
```
- 커밋되는 durable 산출물은 **`targets/**/notes/`, `targets/**/frida/`, `targets/INDEX.md`** 뿐. 바이너리·jadx-out·unpacked·ghidra 프로젝트는 .gitignore로 전부 제외(새 체크아웃엔 없을 수 있음).
- **분석 결론은 반드시 `notes/` 안에만** 쓴다.

### 1-3. criteria + 2-pass (오늘 도입분)
- `docs/criteria/` = OWASP MAS 기반 분석기준. `10-resilience.md`, `50-network.md`, `_template.md`, `00-index.md`.
- 모든 발견은 **메타블록 형식**(`### [RES-XXX-NN]` + 신뢰도/표준/위치/근거/우회(가설)/2차 메모)으로 적고 **criterion ID 태깅 필수**. 안 맞으면 `[신규후보]`.
- **1차(rev-native)는 모든 발견을 `가설`로 고정**, **2차(rev-verify)가 확정/기각으로 갱신**. (근거: scn00 실측에서 rev-native가 기존 java 분석을 재생산 → "재분석이 아니라 태깅·검증 레이어를 얹는다"로 규칙화)

## 2. 내가 물어본 것들 (헷갈렸던 지점) + 확정된 답

> 이 섹션이 오늘 세션의 알맹이. 같은 걸 또 헷갈리면 여기 먼저 볼 것.

### Q. Frida로 우회하려면 `libscn00monitor.so` 말고 **다른 파일**을 대상으로 해야 하나?
**아니다.** scn00에서 보안 로직이 든 `.so`는 `libscn00monitor.so` **하나뿐**(나머지 RN/Hermes는 triage에서 `skip`). 바꿀 다른 파일이 애초에 없음.
- 단, **무엇을 우회하냐**로 갈림:
  - **RASP(루트·Frida·디버거·네이티브 SPKI 피닝) 우회** → `libscn00monitor.so`가 정답.
  - **실제 송금 인증 우회(F28)** → **서버 측** 문제라 후킹할 `.so` 로직 없음. 다만 `nativeSignedReportPinning`의 **네이티브 피닝**이 Burp 중계의 1차 장애물(일반 Java SSL unpinning으론 안 풀림).
- **중요 함정**: 이 `.so`엔 `if(detected) finish()` 같은 **"뒤집을 분기"가 없다**. 증거 수집→서명 리포트 생성만 하고 판정·차단은 서버(`lab.eqst.co.kr`). → Frida 전략은 분기패치가 아니라 **collector 반환값을 빈 문자열/음성으로 후킹**. Frida 탐지는 **3경로(maps·thread명·27042/27043 포트)**라 셋 다 막아야 함(하나만 막으면 음성화 실패).

### Q. 분석대상 `.so`는 "Ghidra에 열린 파일"이냐, "APK에서 푼 `.so` 전체"냐?
**둘 다 아님.** 3단 구조:
1. **후보군** = APK에서 푼 `.so` 전부(`unpacked/lib/arm64-v8a/`). arm64-v8a 한 아키텍처만(32bit 중복 금지).
2. **대상 선정** = `rev-jadx`가 보안 신호로 점수화 → **`triage.md` 맨 아래 전수 체크리스트(so/신호/우선순위/상태)**.
3. **실제 분석** = 체크리스트 우선순위 순서로 하나씩.
→ "전체"는 후보일 뿐, **실제 대상은 triage가 골라낸 것**.

### Q. Ghidra에 여는 건 사람이 하니 "사람이 정한다" 아닌가?
**절반만 맞다.** 사람은 CodeBrowser에 import하는 **집행자**이지 자유 선택이 아님. `rev-native`가 *"열린 `.so`가 목록의 어느 것인지 함수수·심볼로 대조"*해서 검증함. → **결정권은 triage.md, 집행은 사람.**

### Q. "어떤 `.so`를 열라"고 어디서 알려주나? 우선순위는 어디서 확인?
- **열라는 지시** = 각 명령 **마무리 안내 문구**(rev-jadx 끝/rev-all §3 게이트/rev-native §4 "다음은 `<so>`"). 그 값은 Claude가 triage 체크리스트에서 뽑아 채움.
- **우선순위 확인(정본)** = `targets/<target>/notes/triage.md` 맨 아래 **전수 체크리스트 표**(pending/done/skip + 우선순위 숫자). 커밋돼서 세션 바뀌어도 남음 = **source of truth**.
- (보조) jadx 직후 화면 요약에도 뜨지만 휘발성. 기준은 항상 triage.md.

### Q. 후순위 `.so`를 Ghidra에 여는 건 **자동**인가?
**아니다. 항상 수동.** Ghidra import는 파이프라인의 **유일한 수동 게이트**. 1위든 후순위든 매번 사람이 File→Import→Analyze. 시스템이 해주는 건 "다음에 뭘 열어라" **안내 문구 출력까지**. (Claude는 CodeBrowser 조작 불가, MCP는 *열린* 프로그램을 읽기만 함.)
- **scn00 한정**: 후순위가 전부 `skip`이라 **추가로 열 `.so` 없음**. Frida 좌표는 이미 분석 끝난 `libscn00monitor.so.md`의 `우회(가설)` 필드에 다 있음 → Frida 단계에서 Ghidra 다시 안 만져도 됨.
